# ZeroWiki 에이전트 팀 운영

이 디렉터리는 팀 에이전트의 지침·상태·저널을 담는다. 에이전트 팀 기능 자체의 사용법은 `docs/에이전트-팀-운영-가이드.md`를 본다.

## 계층 구조

```
.claude/CONSTITUTION.md              절대 불변 헌법 — 편집 불가, 사용자만 변경
  └─ .claude/team/{역할}/CLAUDE.md   역할 지침 — 해당 에이전트가 수정 가능
       ├─ STATE.md                   현재 상태 스냅샷 (덮어쓰기)
       └─ WORKLOG.md                 작업 저널 (append-only)
```

충돌 시 항상 헌법이 우선한다. 하위 지침에 헌법과 어긋나는 조항이 있으면 그 조항은 무효다.

루트 `CLAUDE.md`는 모든 세션에 자동 로드되며 헌법을 가리키는 포인터 역할을 한다.

| 문서 | 소유자 | 지정일 | 근거 |
| --- | --- | --- | --- |
| `docs/ZeroWiki-요구사항-정의서.md` | 리더 | 2026-07-29 | 기획서(pm)와 API 명세(리더) 사이의 계약 문서이며, ERD·API 양쪽의 상위 근거이므로 특정 구현 역할에 두지 않는다 |

요구사항 정의서는 기획서의 파생 문서다. 기획서가 바뀌면 pm이 리더에게 알리고, 리더가 요구사항 정의서를 갱신한 뒤 backend·frontend에 전파한다.

## 팀원 타입

`.claude/agents/`에 네 정의가 있다. 팀원과 서브에이전트 양쪽에 재사용한다.

| 타입 | 역할 |
| --- | --- |
| `zerowiki-backend` | 데이터 모델·서버·Worker |
| `zerowiki-frontend` | 화면·클라이언트·UX |
| `zerowiki-qa` | 검증·테스트·보안·계약 통합 |
| `zerowiki-pm` | 종합·기획 피드백·결정 추적·우선순위 권고 (헌법 v1.1 신설) |

정의 본문은 팀원 시스템 프롬프트에 **추가**되며(대체 아님) 필독 파일 경로를 포함한다. `.claude/team/` 아래 파일은 계층 자동 로드 대상이 아니므로 이 경로 명시가 로드를 보장한다.

주의: 서브에이전트 정의의 `skills`·`mcpServers` frontmatter는 팀원으로 실행될 때 적용되지 않는다(가이드 4.3).

## 스폰 프롬프트 템플릿

팀원은 리더의 대화 기록을 상속하지 않는다. 읽어야 할 문서 경로를 항상 명시한다(가이드 10.1).

```text
zerowiki-backend 타입으로 backend 라는 이름의 팀원을 스폰해라. 프롬프트:
"너는 ZeroWiki의 backend다. 먼저 .claude/CONSTITUTION.md,
.claude/team/backend/CLAUDE.md, .claude/team/backend/STATE.md를 순서대로 읽어라.
그다음 <작업 내용>. 참조 문서: <경로 + 절 번호>.
결과는 <산출물 경로>에 쓰고, 턴 종료 전 STATE.md와 WORKLOG.md를 갱신해라."
```

frontend·qa도 동일한 형태로 경로만 바꾼다. 팀원 이름은 `backend`·`frontend`·`qa`로 고정해 두면 이후 지목이 쉽다.

## 운영 원칙

- 표시 모드는 `in-process` 고정 (Windows Terminal은 분할 창 미지원, 가이드 5절).
- 팀 크기 3~4명(backend·frontend·qa + 필요 시 pm). 팀원당 5~6개 작업이 적정(가이드 10.2, 10.3).
- **pm은 상시 스폰 대상이 아니다.** 세 역할의 산출물이 쌓여 종합할 것이 생겼을 때, 또는 사용자 결정 요청서가 필요할 때 스폰한다. 종합할 대상이 없는 상태에서 pm을 띄우면 빈 보고서만 나온다.
- 같은 파일을 두 팀원이 편집하지 않도록 소유권 표를 지킨다(가이드 10.5).
- 리더가 위임 대신 직접 구현하기 시작하면 "팀원들이 작업을 마칠 때까지 기다려라"로 교정한다(가이드 10.6).
- in-process 팀원은 `/resume`으로 복원되지 않는다. 세션이 끊기면 팀원을 새로 스폰하고, 각 역할의 `STATE.md`가 재개 지점을 제공한다(가이드 13절).
- 위험한 작업에는 계획 승인을 요구한다: "변경 전에 계획 승인을 요구해라"(가이드 4.4).

## 완료 보고 규약 (2026-07-31 신설)

**보고는 검증 근거와 함께 온다. 근거 없는 완료 보고는 리더가 접수하지 않는다.**

헌법 제7조 5항이 이미 "잔존 참조 검증은 눈으로 하지 않는다 — 검색 명령과 결과를 보고에 첨부한다"고 규정하지만, 그 조항은 **이름 변경·이동·삭제**에만 걸린다. 이 절은 그 범위를 **모든 완료 보고**로 넓힌다. 2026-07-31 세션에서 팀원의 완료 보고가 실제 파일과 어긋난 사례가 네 번 나왔고, 넷 다 이 규약이 있었다면 본인이 먼저 발견했을 것들이다.

### 1. 보고 전에 실제 결과를 다시 읽는다

편집한 파일을 **다시 열어 확인한 뒤** 보고한다. 편집 도구가 성공을 반환한 것과, 의도한 내용이 저장된 것은 다르다.

**보고문에 "수정 결과"라며 코드나 데이터를 붙일 때는 반드시 파일에서 읽어온 것을 붙인다.** 머릿속의 의도를 타이핑해 붙이지 않는다. *(실제 사례: 템플릿 수정 보고에 고쳐진 내용을 첨부했으나, 실제 파일에는 잘못된 값이 그대로 남아 있었다.)*

### 2. 검증 명령과 그 출력을 보고에 붙인다

작업 유형별 최소 근거다.

| 작업 | 첨부할 것 |
| --- | --- |
| 문서·설정 수정 | 고친 문구를 찾는 `grep` 명령과 출력 (잔존 0을 출력으로 보인다) |
| 코드 수정 | 타입체크·빌드 결과 + **해당 동작을 실제로 확인한 근거** |
| 이름 변경·이동·삭제 | 옛 경로·옛 이름·옛 절 번호 검색 결과 (헌법 제7조 5항) |
| 수치·건수 기재 | 정본 문서를 직접 센 명령과 출력 (헌법 제7조 8항) |

"확인했다"·"모두 반영했다"는 근거가 아니다. 명령과 출력이 근거다.

### 3. 행 번호를 믿지 말고 내용으로 검색한다

지시받은 행 번호는 **자기가 앞부분을 고치는 순간 밀린다.** 그 자리만 보고 넘어가면 뒤쪽 잔존을 놓친다. 위치가 아니라 **문구로 검색**해서 잔존 여부를 확인한다. *(실제 사례: "351행·396행을 고쳐라"는 지시를 받고 앞부분을 먼저 고쳐 358·403행이 됐는데, 원래 번호 자리만 확인하고 "모두 수정"으로 보고했다.)*

### 4. 구조적 공백을 스스로 점검한다

빌드가 통과하고 화면이 렌더링된다고 동작하는 것이 아니다. 보고 전에 자문한다.

- 만든 것 중 **데이터 공급원이 없어 영원히 비는** 요소가 있는가 (빈 탭·빈 목록·도달 불가 분기)
- 정의했으나 **아무도 쓰지 않는** 타입·필드·함수가 있는가
- 계약에 없는 값을 화면이 **지어내고** 있지는 않은가

발견하면 고치거나, 못 고치면 **보고에 명시한다.** 리더가 나중에 찾아내면 그건 미완료 작업이다. *(실제 사례: 3단계 필터 탭을 만들었으나 계약이 2단계뿐이라 중간 탭이 구조적으로 항상 비었고, 빌드·렌더링은 통과했다.)*

### 5. 부분 완료는 부분 완료라고 보고한다

일부만 했으면 "일부 완료 + 남은 것"으로 보고한다. 전부 했다고 보고하고 리더가 잔존을 찾아내는 것이 팀에 가장 비싼 실패다 — 왕복이 늘고, 그 사이 다른 팀원이 틀린 정보를 근거로 판단한다.

### 6. 리더의 의무

리더는 완료 보고를 **받은 대로 믿지 않는다.** 근거가 붙어 있어도 중요한 산출물은 직접 열어 확인하고, 근거가 없으면 반려한다. 검증 결과와 반려 사유는 `.claude/team/JOURNAL.md`에 남긴다.

### 2026-07-31 삭제 기록 (헌법 제7조 9항)

**무엇을:** "현재 상태 (2026-07-27)" 절의 본문 — `Phase 0 이전, 코드 없음`, `미확정 계약 20건(API 18절 10 + ERD 8절 10), 이 중 8건 사용자 결정 필요`, 그리고 역할별 다음 작업 표 4행.

**왜:** 2026-07-27 시점 스냅샷이며 넉 달치 진행과 전면 배치된다. 미확정 계약은 20건이 아니라 확정 19건·미확정 10건이고, "코드 없음"은 frontend 화면 2종 구현으로 사실이 아니며, 다음 작업 표의 항목은 대부분 완료됐다. **헌법 제7조 8항**이 변하는 수치를 지침에 고정 기재하지 말고 정본 위치와 세는 방법을 적으라고 규정하므로, 같은 형태로 다시 쓰지 않고 포인터 표로 대체했다.

**어디로:** 버린 것이 아니라 각 정본이 이미 보유하고 있다 — 진행 상황은 각 역할 `STATE.md`와 `docs/PM-종합-현황.md`, 미확정 계약은 `docs/ZeroWiki-요구사항-정의서.md` 12절, 시간순 이력은 `.claude/team/JOURNAL.md`. **판단·권고·근거에 해당하는 내용은 없었고**(전부 시점 사실과 작업 목록), 따라서 제7조 9항 3번째 항목의 리더 승인 대상에 해당하지 않는다.
