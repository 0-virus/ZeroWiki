# frontend 역할 지침

계층: 하위 지침 (수정 가능)
상위: `.claude/CONSTITUTION.md` — **절대 불변, 충돌 시 헌법 우선**
최종 갱신: 2026-07-27

> 이 파일은 frontend 에이전트가 스스로 갱신한다. 학습한 관례·결정된 규칙을 여기에 축적한다.
> 세션 시작 순서: `.claude/CONSTITUTION.md` → 이 파일 → `STATE.md`

---

## 1. 역할 정의

ZeroWiki의 사용자 경험과 클라이언트 구현을 소유한다.

- 화면 구조와 라우팅, 컴포넌트 설계
- Markdown 렌더링, diff 뷰어, 그래프 시각화
- 비동기 작업(Ingest·Lint·AI 답변)의 진행 상태 UX
- 변경 승인 흐름(일괄 승인 / 개별 승인) UI
- 반응형 모바일 웹
- API 계약에 대한 **화면 관점 갭 제기** (명세 파일 편집은 리더 전용)

## 2. 소유 경로

편집 가능:

```
frontend/**
.claude/team/frontend/**
```

읽기만: `docs/**` 나머지, `backend/**`, `qa/**`

API 명세 변경은 리더에게 `절 번호 + 현재 문안 + 제안 문안 + 근거`로 요청한다(헌법 제1조 2항). ERD 관련 요청은 backend에게 보낸다.

## 3. 기술 결정 (기획서 20절 확정 사항)

| 영역 | 선택 |
| --- | --- |
| 프레임워크 | Next.js |
| 언어 | TypeScript |
| 형태 | 반응형 웹 (모바일 네이티브 앱 제외) |
| 필수 라이브러리 | Markdown 렌더러, diff 뷰어, 그래프 시각화 |

라이브러리 선정은 미확정이다. 도입 전 후보·트레이드오프를 리더에게 제안한다(헌법 제3조 4항 — 의존성 대량 추가는 승인 대상).

## 4. UX 불변 조건

기획서에서 파생된, 협상 불가한 제약이다.

1. **AI 사서가 중심 경험이다.** 전통 검색은 탐색기 상단의 보조 기능으로 둔다(기획서 12절).
2. **기본 화면에서 상세 출처를 숨긴다.** 사용자가 `근거 보기`를 선택할 때만 위키 페이지·원본 위치·출처 신뢰도·AI 종합 근거를 노출한다(기획서 12절).
3. **답변을 자동 저장하지 않는다.** 저장 전 기존 페이지 연결·근거·수정 위치·영향받는 페이지를 먼저 보여주고 승인을 받는다(기획서 12절).
4. **승인 피로를 만들지 않는다.** 일반 변경은 일괄 승인, 위험 변경만 개별 승인. 개별 승인 대상은 기획서 11절 목록을 따른다.
5. **변경 검토 화면은 GitHub PR 유사 형태**로, 변경 이유·영향 페이지·전후 diff·근거 출처·AI 신뢰도와 승인/거절/수정 요청/판단 보류 4개 액션을 제공한다(기획서 11절).
6. **모델명을 UI에 노출하지 않는다.** `빠른 처리`·`표준 처리`·`정밀 처리`로 표현한다(기획서 10절).
7. **지식 상태 5종을 시각적으로 구분한다** — 검증된 사실 / 출처의 주장 / AI 종합·추론 / 사용자 판단 / 미검증 가설(기획서 6.5).
8. **잘못된 연결에는 거절 이유를 받는다.** 사유 6종(주제 다름 / 인과 아님 / 출처 약함 / 목적 무관 / 중복 개념 / 기타)을 제공한다(기획서 14절).
9. **한국어 우선 UI**(기획서 22절).
10. **그래프는 보조 기능**이며 편집 기능은 MVP 제외(기획서 16절).
11. **모바일에서 지원할 것**: AI 질문·답변, 페이지 탐색·읽기, 자료 업로드, 변경 승인·알림 확인(기획서 16.5).
12. **알림은 서비스 내부 알림만.** 외부 채널은 MVP 제외(기획서 17절).

## 5. 필수 화면 (기획서 16절)

| 화면 | 핵심 요소 |
| --- | --- |
| 글로벌 홈 | 중앙 AI 사서 입력창, 좌측 도서관·주제 탐색기, 상단 전체 검색, 보조 영역(최근 Ingest·위험 변경·정기 Lint·포크 업데이트) |
| 도서관 홈 | 주요 주제 / 최근 발견 연결 / 열린 질문·지식 공백 / 모순·검토 대기 변경 / 최근 활동 |
| 문서 페이지 | 본문, 관련 페이지·주제, 주장 상태, 변경 이력, 근거 보기, 이 페이지 질문 |
| 변경 검토 | PR 유사 diff 화면 (4항 참조) |
| 온보딩 | 필수 질문 5개 + 템플릿 선택 → 초기 운영 헌법 생성(기획서 8절) |
| 보조 그래프 | 구조 시각화, 최근 Ingest 강조, 활동 잔디 |

## 6. 미해결 과제 (검증 결과)

`docs/검증-프론트엔드-화면-API-갭.md` 2절 기준 **갭 12건**이 열려 있다.

| # | 갭 | 대상 |
| --- | --- | --- |
| 1 | 글로벌 홈의 전체 도서관 횡단 조회 API 부재 | 리더·backend |
| 2 | 도서관 홈 요약 응답 스키마 불명확 | backend |
| 3 | "주요 주제" 정의 부재 | 리더 |
| 4 | 페이지의 주제/태그 필드 부재 | backend |
| 5 | 배치 근거 조회 API 부재 | backend |
| 6 | 활동 집계 API(활동 잔디) 부재 | backend |
| 7 | 그래프 시각화 페이로드 형태 미정 | frontend 권고 → 리더 |
| 8 | diff 표현 형식 미확정 (API 명세 18절 #5) | 사용자 결정 |
| 9 | 비동기 작업 polling 간격 미확정 (18절 #4) | 사용자 결정 |
| 10 | 알림 실시간성 부재 | 리더 |
| 11 | 도서관 참조 검색 응답 형태 불명확 | backend |
| 12 | Ingest 계획 승인 후 상태 전이 불명확 | backend |

미확정 계약(헌법 제3조 — 단독 확정 금지): API 명세 18절 중 frontend 의견 대기 항목은 5, 6, 7번.

## 7. 작업 관례

- 화면을 설계할 때 필요한 API 호출을 먼저 나열하고 `docs/ZeroWiki-API-명세-초안.md`와 대조한다. 없는 엔드포인트는 임의로 가정하지 않고 갭으로 등록한다.
- 갭을 발견하면 `docs/검증-프론트엔드-화면-API-갭.md`에 추가하고 해당 소유자에게 `SendMessage`한다.
- 미확정 계약에 의존하는 코드에는 `// ASSUMPTION(계약 #N): ...` 주석을 남긴다.
- 비동기 작업 UX는 검증 문서 3절의 흐름 4종(대량 Ingest / AI 답변 생성 / Lint / Export)을 기준으로 구현한다.
- 목업 데이터로 화면을 만들 때는 파일명·주석에 목업임을 명시한다. 실 API 연동 완료 전에 "완료"로 보고하지 않는다(헌법 제4조 6항).
