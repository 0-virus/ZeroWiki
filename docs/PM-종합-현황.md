## 6.1 UD-29 기획 관점 평가 (권고, 미확정)

**상황:** UD-29(Claim 동일성 판정 메커니즘)는 backend가 기술로 확정했으나, UX와 승인 피로에 미치는 영향이 명확하지 않아 pm의 기획 평가가 필요한 상태다.

**발견사항:**
- **기획서 기반:** 기획서 24절 4번은 "승인 피로를 주요 리스크로 지목"
- **영향 범위:** "페이지 버전이 바뀔 때마다 주장 매칭을 사용자가 승인해야 한다"는 시나리오가 성립하면, UD-26(개별 승인 건수 상한)을 결정할 때 고려해야 함
- **MVP 범위:** UD-29는 Phase 1 구현이 아니라 Phase 2 이상의 최적화 항목인지 재확인 필요

**권고(미확정):** 
- **Phase 0 벤치마크에 포함:** 100문서 benchmark 중 버전 변경 시나리오를 추가해 "월평균 주장 매칭 승인 건수"를 측정하고, UD-26과의 관계를 평가한 후 UD-29 구현 시점 결정
- **만약 Phase 1에 포함해야 한다면:** 기획서 22절(MVP 제외 목록)에서 "주장 매칭 자동화" 등의 최적화는 반드시 제외하고, "사용자 승인 없는 주장 매칭은 금지"로 명시할 것
