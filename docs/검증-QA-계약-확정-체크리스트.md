## 1. 문서 목적과 범위

이 문서는 다음을 정의한다:

1. **구현 전 미확정 계약** — 제품 오너(사용자) 결정 필요 vs 기술적 권고안 구분

### 4.1 요구사항 추적 매트릭스 검증 (API 명세 19절)

**조사 대상:** API 19절의 "요구사항 추적" 표가 요구사항 정의서 FR/NFR과 실제로 대응하는가?

| --- | --- | --- | --- |
| 2.7 | FR-ING-20, FR-ING-25 | ✅ 요구사항 정의서 5.5.3절: FR-ING-20 작업 상태 8종, FR-ING-25 조회 API | 일치 |
| 2.8 | FR-ING-13, FR-KNW-06, FR-UIX-12·13 | ✅ 요구사항 정의서 2.8절: 처리 모드 enum, 지식 상태 enum, 언어 규약 (FR-ING-13, FR-KNW-06, FR-UIX-12·13) | 일치 |
| 4.3 | FR-LIB-04·05, NFR-SEC-03 | ✅ 요구사항 정의서 5.2절: FR-LIB-04·05 단방향 참조, NFR-SEC-03 도서관 간 경계 | 일치 |

**결론:** API 19절-15절 매핑이 정확함 ✓. 다만 **UD-28의 결정 주체 불일치** 발견: API 명세 18절(기획pm)과 요구사항 정의서 12.2절(기술)이 다름 → 리더가 정정.

### 4.2 운영 상태 일관성 검증 (FR-ING-26)

**조사 대상:** `CANCELLED`, `PAUSED_QUOTA` 상태가 기획서·API·ERD에 일관되게 정의되는가?

| 문서·항목 | 정의 | 내용 | 일치 여부 |
| --- | --- | --- | --- |
| 기획서 20절 | 정상 흐름 8종 | 기획서의 대량 Import 9단계를 상태 8종으로 정의 | ✅ |
| 요구사항 정의서 5.5.3절 | FR-ING-20 정상 흐름 8종 + FR-ING-26 운영 상태 2종 | QUEUED, SCANNING, PLAN_REVIEW, PROCESSING, QUESTION_REVIEW, CHANGE_REVIEW, COMPLETED, FAILED + **CANCELLED, PAUSED_QUOTA** | ✅ |
| API 명세 2.7절 | 상태 매핑표 | 8종 + 2종 운영 상태 모두 정의, PAUSED_QUOTA는 FAILED와 명확히 구별 | ✅ |
| ERD | `ingest_jobs.status` enum | 체크: 10종 모두 수용 가능 | ⚠️ **미확인** — ERD 4절 이후 읽지 않음. backend가 10종 enum 구현했는지 확인 필요 |

**결론:** API와 요구사항 정의서는 일치. backend가 ERD에서 enum을 올바르게 정의했는지 확인 필요 → backend에게 SendMessage.

### 4.3 미확정 번호 일관성 (UD-01~UD-27)

**조사 대상:** UD 번호가 요구사항 정의서·API 명세·ERD에서 일관되는가?

| UD 범위 | 정본 | API 18절 | ERD 8절 | 상태 |
| --- | --- | --- | --- | --- |
| UD-01~10 | 요구사항 정의서 12.1절 API 계약 10건 | API 18절에 동일 번호로 기재 | 해당 없음 | ✅ 일치 |
| UD-11~20 | 요구사항 정의서 12.1절 ERD 계약 10건 | 명시 없음 (ERD 측 미확정) | ERD 8절에 동일 번호로 기재 | ✅ 일치 |
| UD-21~27 | 요구사항 정의서 12.2절 신규 발견 7건 | API 18절 기재: UD-21(Lint 시각), UD-23(알림 보존) | 해당 없음 | ✅ 일치 |

**결론:** UD 번호 매핑 일관적. 다만 API 18절이 요구사항 정의서 12.2절의 신규 항목(UD-21~27)을 모두 반영했는지 확인 → API 18절에 UD-25(성능 목표), UD-26(승인 피로) 추가 필요 가능.

## 6. 에러 계약과 엣지케이스 커버리지

기준: API 명세 2.3절 "오류 응답", 2.4절 "페이지네이션과 정렬"

### 5.1 HTTP 상태 코드별 에러 케이스

| 상태 | 코드 | 시나리오 | 테스트 케이스 |
| --- | --- | --- | --- |
| **400** | `VALIDATION_FAILED` | JSON 필드 타입 오류 (예: `"limit": "twenty"`) | `POST /libraries` + 잘못된 templateType |
| **400** | `INVALID_STATE_TRANSITION` | 상태 기계 위반 (예: COMPLETED → QUEUED) | `PATCH /ingest-jobs/{id}` + 불가능한 상태 |
| **401** | (없음) | 만료된 Access Token, 없는 token | expired JWT 사용 시 401 반환 |
| **403** | `FORBIDDEN` | 다른 사용자 도서관 수정 시도 | `PATCH /libraries/{otherUserLibraryId}` |
| **404** | `RESOURCE_NOT_FOUND` | 존재하지 않는 페이지 | `GET /libraries/{id}/pages/{nonexistentId}` |
| **409** | `DUPLICATE_SOURCE` | 같은 URL을 두 번 클리핑 | `POST /web-clips` + 중복 URL (초 내 재요청) |
| **409** | `VERSION_CONFLICT` | 기준 버전 변경됨 | `PUT /libraries/{id}/constitution` + 구버전 expectedVersion |
| **409** | `IDEMPOTENCY_KEY_REUSED` | 같은 키 + 다른 본문 | 멱등성 키 불일치 감지 |
| **413** | (없음) | 최대 파일 크기 초과 (200MB) | 300MB 파일 업로드 시도 |
| **422** | `SECRET_DETECTED` | 비밀번호·API 키 탐지 | `.env` 파일 업로드 시도 |
| **429** | `QUOTA_EXCEEDED` | AI 처리량 부족 | 할당량 소진 후 Ingest 시도 |
| **503** | `DEPENDENCY_UNAVAILABLE` | LLM 공급자 장애 | 응답 타임아웃 → 503 + retry 권장 |

### 5.2 페이지네이션 엣지케이스

| 케이스 | 동작 | 검증 |
| --- | --- | --- |
| **0개 결과** | `data: []`, `hasNext: false` | 빈 목록 조회 |
| **정확히 limit만큼** | `hasNext: false` (다음 없음) | limit=20, 결과 20개 |
| **limit 초과** | limit 최대값 100으로 cap | `limit=1000` → 100으로 조정 |
| **cursor 변조** | 자동 복호화 실패 → 400 또는 처음부터 | 잘못된 cursor 포함 조회 |
| **정렬 필드 없음** | 기본 정렬(updatedAt, desc) | 정렬 지정 안 함 |

### 5.3 비동기 작업 엣지케이스

| 케이스 | 동작 | 검증 |
| --- | --- | --- |
| **문서별 실패** | job 상태 COMPLETED, 실패 항목만 표시 | ingest_items.status = FAILED 확인 |
| **부분 승인** | change_set.status = PARTIALLY_APPROVED | 일부 항목만 APPROVED |
| **계획 변경됨** | `409 PLAN_CHANGED` | 승인 중 새 계획 감지 |
| **polling timeout** | 60초 이상 응답 없음 시 nextAction 제시 | `PURCHASE_QUOTA` 등 사용자 액션 필요 |
| **멱등성 키 만료** | 24시간 후 새 결과 생성 | 재요청이 다른 결과 반환 가능 |

### 5.4 데이터 일관성 엣지케이스

| 케이스 | 동작 | 검증 |
| --- | --- | --- |
| **순환 참조** | 도서관 A → B → C → A 방지 | library_references 삽입 시 순환 검사 |
| **원본 삭제 중 참조** | `409 DEPENDENCY_CONFLICT` | 사용 중인 원본 삭제 차단 |
