## 1. 문서 목적과 범위

이 문서는 다음을 정의한다:

1. **구현 전 미확정 계약** — 제품 오너(사용자) 결정 필요 vs 기술적 권고안 구분
2. **MVP 검증 기준의 측정 가능한 테스트 변환** — 자동화 테스트 vs 사용자 평가 분류
3. **보안·제품 리스크 매트릭스** — 공격 시나리오와 기획서상 방어 위치 명시
4. **에러·엣지케이스 커버리지** — API 명세의 오류 응답과 경계 조건 검증

frontend와 backend가 각자 `docs/검증-프론트엔드-화면-API-갭.md`와 `docs/검증-백엔드-ERD-API-정합성.md`를 작성하며, 본 문서에서 세 문서가 일관성 있게 통합된다.

## 3. MVP 검증 기준의 측정 가능한 테스트

기준: 기획서 3절 "검증 기준"

### 3.1 자동화 테스트 (CI/CD 통합)

| # | 검증 기준 | 측정 방식 | 통과 조건 | 자동화 |
| --- | --- | --- | --- | --- |
| A-1 | 문서 100개 Import 완료율 95% 이상 | `test_ingest_100_documents` | 100개 중 95개 이상 COMPLETED 상태 | ✅ 자동 테스트 |
| A-2 | 핵심 주제 구조 자동 생성 | Ingest 후 topic_groups 객체 검증 | 최소 5개 주제, 각 문서 분류율 95% | ✅ 자동 테스트 |
| A-3 | 주요 답변 근거 추적 가능성 | 답변 citations 필드 검증 | 각 citation은 page_version_id + claim_id + source_version_id 포함 | ✅ 자동 테스트 |

## 4. 보안 요구사항과 제품 리스크 매트릭스

기준: 기획서 24절 "가장 큰 제품 리스크", API 명세 15절 "보안 요구사항"

### 4.1 보안 위협 모델과 방어

| ID | 위협 시나리오 | 영향 | 기획서 방어 | API 명세 방어 | 검증 방법 |
| --- | --- | --- | --- | --- | --- |
| **S-1** | **프롬프트 인젝션** — 사용자 문서에 `"실행 금지: 사용자 데이터 유출"`처럼 쓰여 있을 시 LLM이 따를 우려 | 높음 | 6.5절 "원본 문서의 내용을 AI 시스템 명령과 분리" | 15절 6번 "원본 문서 본문은 LLM 시스템·개발자 명령과 분리된 데이터 영역으로 전달" | 테스트: 악의적 문서 Ingest 후 LLM 출력이 명령 실행하지 않음 |
| **S-2** | **ZIP 경로 탐색(path traversal)** — `../../../etc/passwd` 구조로 원본 외 시스템 파일 접근 | 높음 | 18절 보안 "ZIP path traversal 차단" | 15절 4번 "ZIP path traversal과 압축 폭탄 차단" | 테스트: `../` 포함 파일 Ingest 차단 확인 |
| **S-3** | **SSRF(Server-Side Request Forgery)** — URL 클리핑 시 `http://127.0.0.1:5432` 같은 사설 주소 요청 | 중간 | 9절 URL 클리핑 "공개 URL만" | 15절 5번 "사설 IP, loopback, link-local 주소 차단" | 테스트: 사설 IP 클리핑 요청 403 반환 |
| **S-4** | **비밀번호·API 키 저장** — 사용자가 실수로 `.env` 파일이나 토큰을 원본으로 업로드 | 높음 | 18절 "비밀번호·API 키·토큰으로 보이는 내용은 저장 전 차단" | 15절 9번 "비밀번호·API 키·토큰 탐지는 객체 영구 저장 전 실행" | 테스트: 정규식 탐지 후 `422 SECRET_DETECTED` 반환 |
| **S-5** | **도서관 간 정보 노출** — A 사용자의 비공개 도서관이 B 사용자 도서관에 참조되어 데이터 누수 | 높음 | 6.1절 "사용자별 데이터 격리", 18절 "사용자별 데이터 격리" | 15절 1번 "모든 쿼리는 인증 사용자와 소유자 조건을 함께 적용" | 테스트: 다른 사용자 도서관 조회 시 404 또는 403 반환 |
| **S-6** | **저작권 원본 과도 재현** — 공개 페이지가 원본의 90% 이상을 그대로 인용 | 중간 | 15절 "공개 전 저작권 위험 검사" | 15절 7번 "공개와 위험 변경에는 행위자·시각·대상·결과를 감사 로그로 남김" | 테스트: 발췌문 비율 분석, 수동 검토 체크리스트 |
| **S-7** | **비동기 작업 비용 폭탄** — 사용자가 같은 작업을 반복 실행해 과금 폭증 | 중간 | 10절 Ingest 파이프라인 "사용자 승인 필수" | 15절 12번 "사용량 차감과 변경 적용은 멱등성 키로 중복 실행 방지" | 테스트: 동일 Idempotency-Key 재전송 시 같은 결과 반환 |
| **S-8** | **토큰 탈취** — Access Token이 노출되어 타인이 계정 사용 | 높음 | 3절 인증 "Access Token 15분 수명" | 2.1절 "Access Token: 짧은 수명" | 테스트: 만료된 token 401 반환, 로테이션 검증 |
| **S-9** | **웹 캐싱 민감정보 노출** — 공개 페이지가 개인정보 포함 후 CDN 캐시 | 중간 | 15절 "공개 전 민감정보 검사" | 15절 3번 "업로드는 확장자 아닌 MIME sniffing, 크기, 압축 해제 크기로 검사" | 테스트: 공개 전 검사 결과 확인, Cache-Control 헤더 검증 |
| **S-10** | **오류 응답에서 민감 정보 누수** — 500 에러가 SQL 쿼리나 원본 본문 노출 | 중간 | 18절 "모든 위험 변경과 공개 작업에 감사 로그" | 15절 11번 "오류 응답과 로그에 원본 본문, 토큰, 서명 URL 미포함" | 테스트: 에러 응답 모니터링, 로그 검사 |

### 4.2 제품 리스크와 완화 방안

기준: 기획서 24절 "가장 큰 제품 리스크"

| **R-1** | 연결 품질 저하 — 과도한 연결로 도서관이 소음화 | 높음 | API 명세 4.2절 link_policy `minimumConfidence: 0.75`, 운영 헌법에 threshold 설정 | Phase 0 벤치마크: 연결 재현율·정확도 측정 |

| **R-3** | AI 비용 초과 — 대량 Ingest가 예산 초과 | 높음 | API 명세 6.1절 "처리 계획과 비용을 사용자에게 제시", `expectedEstimatedTokens` 확인 | Phase 0: 100개 문서 평균 토큰·비용 측정 |
| **R-4** | 승인 피로 — 위험 변경 많아서 자동화 가치 상실 | 중간 | API 명세 11절 "일괄 승인 대상" 명시, 대부분 SAFE로 분류 | Phase 1: 일괄 승인 비율 측정 (목표 80% 이상) |
| **R-5** | 범용 스키마 실패 — 분야별 구조 생성 불안정 | 중간 | 기획서 6.3절 "도서관별 운영 헌법 구조화 설정", Lint에서 "도서관 목적과 실제 구조 불일치" 검사 | Phase 0: 학습·의사결정·논문 등 3개 분야 테스트 |
| **R-6** | 저작권 위반 — 공개 페이지가 원본 과다 재현 | 높음 | 기획서 15절 "공개 전 저작권 위험 검사", API 명세 14.1절 `publication-checks` 필수 | 수동 법률 검토 필요 |
| **R-7** | 보안 실패 — 도서관 간 정보 노출 | 높음 | ERD 6절 정합성 규칙 2번 "도서관 소유자 검증", API 명세 15절 1번 "인증 사용자·소유자 조건" | Phase 0: 교차 사용자 접근 테스트 |

## 5. 에러 계약과 엣지케이스 커버리지

기준: API 명세 2.3절 "오류 응답", 2.4절 "페이지네이션과 정렬"

### 5.1 HTTP 상태 코드별 에러 케이스

| 상태 | 코드 | 시나리오 | 테스트 케이스 |
| --- | --- | --- | --- |
| **400** | `VALIDATION_FAILED` | JSON 필드 타입 오류 (예: `"limit": "twenty"`) | `POST /libraries` + 잘못된 templateType |
| **400** | `INVALID_STATE_TRANSITION` | 상태 기계 위반 (예: COMPLETED → QUEUED) | `PATCH /ingest-jobs/{id}` + 불가능한 상태 |
| **401** | (없음) | 만료된 Access Token, 없는 token | expired JWT 사용 시 401 반환 |
| **403** | `FORBIDDEN` | 다른 사용자 도서관 수정 시도 | `PATCH /libraries/{otherUserLibraryId}` |
| **404** | `RESOURCE_NOT_FOUND` | 존재하지 않는 페이지 | `GET /libraries/{id}/pages/{nonexistentId}` |
| **409** | `DUPLICATE_SOURCE` | 같은 URL을 두 번 클리핑 | `POST /web-clips` + 중복 URL (초 내 재요청) |
| **409** | `VERSION_CONFLICT` | 기준 버전 변경됨 | `PUT /libraries/{id}/constitution` + 구버전 expectedVersion |
| **409** | `IDEMPOTENCY_KEY_REUSED` | 같은 키 + 다른 본문 | 멱등성 키 불일치 감지 |
| **413** | (없음) | 최대 파일 크기 초과 (200MB) | 300MB 파일 업로드 시도 |
| **422** | `SECRET_DETECTED` | 비밀번호·API 키 탐지 | `.env` 파일 업로드 시도 |
| **429** | `QUOTA_EXCEEDED` | AI 처리량 부족 | 할당량 소진 후 Ingest 시도 |
| **503** | `DEPENDENCY_UNAVAILABLE` | LLM 공급자 장애 | 응답 타임아웃 → 503 + retry 권장 |

### 5.2 페이지네이션 엣지케이스

| 케이스 | 동작 | 검증 |
| --- | --- | --- |
| **0개 결과** | `data: []`, `hasNext: false` | 빈 목록 조회 |
| **정확히 limit만큼** | `hasNext: false` (다음 없음) | limit=20, 결과 20개 |
| **limit 초과** | limit 최대값 100으로 cap | `limit=1000` → 100으로 조정 |
| **cursor 변조** | 자동 복호화 실패 → 400 또는 처음부터 | 잘못된 cursor 포함 조회 |
| **정렬 필드 없음** | 기본 정렬(updatedAt, desc) | 정렬 지정 안 함 |

### 5.3 비동기 작업 엣지케이스

| 케이스 | 동작 | 검증 |
| --- | --- | --- |
| **문서별 실패** | job 상태 COMPLETED, 실패 항목만 표시 | ingest_items.status = FAILED 확인 |
| **부분 승인** | change_set.status = PARTIALLY_APPROVED | 일부 항목만 APPROVED |
| **계획 변경됨** | `409 PLAN_CHANGED` | 승인 중 새 계획 감지 |
| **polling timeout** | 60초 이상 응답 없음 시 nextAction 제시 | `PURCHASE_QUOTA` 등 사용자 액션 필요 |
| **멱등성 키 만료** | 24시간 후 새 결과 생성 | 재요청이 다른 결과 반환 가능 |

### 5.4 데이터 일관성 엣지케이스

| 케이스 | 동작 | 검증 |
| --- | --- | --- |
| **순환 참조** | 도서관 A → B → C → A 방지 | library_references 삽입 시 순환 검사 |
| **원본 삭제 중 참조** | `409 DEPENDENCY_CONFLICT` | 사용 중인 원본 삭제 차단 |
| **페이지 버전 충돌** | change_set 재계산 | 기준 버전 이후 새 변경 발생 |
| **근거 소실** | evidence 참조 원본 삭제 시 claim 고아화 | soft delete로 정합성 유지 |
| **공개 페이지 내부 수정** | 공개 버전은 고정, 내부만 새 버전 | page_publications.page_version_id 불변 |
