## 1. 화면 개요

Ingest(대량 Import) 작업의 진행 상태를 실시간으로 표시하는 화면.

**주요 기능**:
1. 작업 진행도 (단계별 상태 + 진행 바)
2. PAUSED_QUOTA vs FAILED 시각 구분 (갭 #15)
3. 토큰 만료 중 자동 재발급 (갭 #20, UD-02)
4. 업로드 한도 사전 검증 (갭 #19, UD-01)
5. 사용자 액션 (계획 승인, 질문 답변, 변경 검토 등)

## 2. 작업 상태 흐름 (FR-ING-20 + FR-ING-26)

### 2.1 정상 흐름 (8종)

`
QUEUED → SCANNING → PLAN_REVIEW
  ↓
PROCESSING → QUESTION_WAITING
  ↓
CHANGE_REVIEW → COMPLETED
`

또는:

`
FAILED (종결)
`

### 2.2 운영 상태 (2종, FR-ING-26)

- **CANCELLED**: 사용자가 작업 취소
- **PAUSED_QUOTA**: 처리량 부족으로 중단 (구매 후 재개 가능)

### 2.3 상태별 UI 표현

| 상태 | 색상 | 아이콘 | 사용자 액션 |
| --- | --- | --- | --- |
| QUEUED | 회색 | ⏳ | (대기 중) |
| SCANNING | 파란색 | 🔍 | (진행도 표시) |
| PLAN_REVIEW | 파란색 | 📋 | [계획 승인] 필수 |
| PROCESSING | 파란색 | ⚙️ | (진행도 표시) |
| QUESTION_WAITING | 노랑색 | ❓ | [답변] 필수 |
| CHANGE_REVIEW | 주황색 | 📝 | [검토] 필수 |
| COMPLETED | 초록색 | ✓ | (완료) |
| FAILED | 빨강색 | ✗ | [재시도] 또는 (종결) |
| PAUSED_QUOTA | 주황색 | ⏸️ | [처리량 구매] |
| CANCELLED | 회색 | ⊘ | (취소됨) |

## 3. 화면 레이아웃

### 3.1 상단 메타데이터

`
╔════════════════════════════════════════╗
║ 대량 Import: "2026-07-30 논문 모음"    ║
║ 상태: 처리 중 (계획 승인 완료)         ║
║ 진행도: 67개 완료 / 100개 (67%)       ║
║ 예상 시간: 약 3분 남음                 ║
╚════════════════════════════════════════╝
`

**표시 정보**:
- 작업 이름 (사용자 지정)
- 현재 상태 (색상 배지)
- 진행도 (완료 수 / 총 수)
- 예상 남은 시간

### 3.2 진행 바

`
┌─────────────────────────────────────┐
│ 처리 중                             │
│ ████████████████░░░░░░░░░░░░░░░░░░ │ 67%
│                                     │
│ 문서별 처리:                        │
│ ✓ 63개 완료                         │
│ ⚙️  1개 처리 중 (inference.md)     │
│ ⏸️  1개 보류 (처리량 부족)          │
│ ✗ 0개 실패                          │
│ ⏳ 35개 대기 중                      │
└─────────────────────────────────────┘
`

**요소**:
- 진행 바 (기본 회색)
- 단계별 통계 (완료/처리/보류/실패/대기)
- 현재 처리 중인 문서명

## 4. PAUSED_QUOTA vs FAILED 시각 구분 (갭 #15)

### 4.1 FAILED (종결 상태, 빨강색)

`
┌─────────────────────────────────────┐
│ ✗ FAILED - 처리 실패                │
├─────────────────────────────────────┤
│                                     │
│ 이유: API 서버 오류 (500)          │
│                                     │
│ 실패한 문서: 3개                    │
│ - document_1.pdf                    │
│ - document_2.pdf                    │
│ - document_3.pdf                    │
│                                     │
│ 해결책:                             │
│ 1. 실패한 문서 확인                │
│ 2. [재시도] 버튼으로 다시 처리      │
│                                     │
│         [재시도] [로그 보기]        │
└─────────────────────────────────────┘
`

**특징**:
- 빨강색 배경 (경고)
- ✗ 아이콘 (종결)
- "재시도" 버튼 (선택 가능)

### 4.2 PAUSED_QUOTA (복구 가능, 주황색)

`
┌─────────────────────────────────────┐
│ ⏸️  PAUSED_QUOTA - 보류 중           │
├─────────────────────────────────────┤
│                                     │
│ 처리량 부족으로 일시 보류되었습니다  │
│                                     │
│ 현재 처리량: 0 / 100 (소진됨)      │
│ 보류된 문서: 35개                    │
│                                     │
│ 다음 조치:                          │
│ 1. 처리량 추가 구매                │
│ 2. [계속하기] 버튼으로 재개         │
│                                     │
│  [처리량 구매 ()] [계속하기]     │
│                                     │
│ 💡 팁: 이전에 완료한 67개 문서는    │
│    자동으로 도서관에 추가됩니다      │
└─────────────────────────────────────┘
`

**특징**:
- 주황색 배경 (경고이지만 해결 가능)
- ⏸️ 아이콘 (일시 보류)
- "처리량 구매" 버튼 (구매 유도)
- "계속하기" 버튼 (재개)
- 팁: 진행 상황 설명

## 5. 업로드 한도 검증 (갭 #19, UD-01)

### 5.1 사전 검증 (파일 선택 시)

**한도 (UD-01 확정)**:
- 파일당: 200MB
- ZIP당: 1GB
- Import당: 1000개 문서

**구현**:
`
파일 선택 시:
1. 클라이언트 측 크기 확인
2. 초과 시 경고 메시지 표시
3. 업로드 진행도 표시 (ZIP 압축해제 후)
`

**UI 예시**:
`
┌─────────────────────────────────────┐
│ 📁 파일 선택                         │
├─────────────────────────────────────┤
│                                     │
│ [파일 선택]  논문_모음.zip          │
│                                     │
│ 파일 크기: 850MB (한도: 1GB) ✓     │
│                                     │
│ 압축해제 후 문서 개수:              │
│ 약 120개 (한도: 1000개) ✓          │
│                                     │
│ 아래 한도를 초과하면 업로드 불가:  │
│ • 파일당 200MB                      │
│ • ZIP당 1GB                         │
│ • Import당 1000개 문서              │
│                                     │
│          [업로드 시작]              │
└─────────────────────────────────────┘
`

### 5.2 413 에러 처리 (서버 거절)

**상황**: 업로드 중 서버에서 413 (Payload Too Large) 응답

**UI**:
`
┌─────────────────────────────────────┐
│ ⚠️  파일이 너무 큽니다              │
├─────────────────────────────────────┤
│                                     │
│ 파일 또는 문서 개수가 한도를 초과했 │
│                                     │
│ 현재: 1200개 문서 (한도: 1000개)   │
│                                     │
│ 해결책:                             │
│ 1. ZIP을 여러 개로 분할             │
│ 2. 개별 파일로 업로드               │
│                                     │
│ 예: 600개 + 600개로 나누기          │
│                                     │
│         [다시 시도] [취소]         │
└─────────────────────────────────────┘
`

## 6. 토큰 만료 중 polling 처리 (갭 #20, UD-02)

### 6.1 토큰 수명 (UD-02 확정)

- **Access Token**: 15분
- **Refresh Token**: 30일

### 6.2 Polling 중 401 처리

**상황**: 진행 중인 Ingest에서 토큰 만료

**대응**:
1. 401 응답 감지
2. Refresh Token으로 자동 재발급
3. 같은 jobId로 polling 재개
4. 사용자에게는 진행도 표시만 (투명성)

**구현 위치**: axios/fetch 인터셉터

`javascript
// 요청 인터셉터
if (response.status === 401) {
  // 1. Refresh Token으로 새 Access Token 발급
  const newAccessToken = await refreshToken();
  
  // 2. 원래 요청 재시도 (같은 jobId)
  return retryOriginalRequest(newAccessToken);
}
`

**실패 케이스**:
`
Refresh Token도 만료 시:
→ "세션이 만료되었습니다. 다시 로그인하세요"
→ 로그인 화면으로 리다이렉트
`

**다중 탭 처리**:
- 한 탭이 토큰 갱신 → LocalStorage 이벤트
- 다른 탭들도 토큰 동기화

## 7. 필요한 API

### 7.1 Ingest 작업 조회

`http
GET /libraries/{libraryId}/ingest-jobs/{jobId}
`

**응답**:
- id, status (QUEUED·SCANNING·PLAN_REVIEW·PROCESSING·...)
- progress (completed, total)
- nextAction (APPROVE_PLAN·ANSWER_QUESTIONS·REVIEW_CHANGES)
- plan (계획 정보)
- questions (AI 질문 배열)
- changeSetId (변경 세트 ID)

### 7.2 계획 승인

`http
POST /libraries/{libraryId}/ingest-jobs/{jobId}/approve-plan
`

### 7.3 질문 답변

`http
POST /libraries/{libraryId}/ingest-jobs/{jobId}/answer
`

### 7.4 변경 검토

`http
GET /libraries/{libraryId}/change-sets/{changeSetId}
POST /libraries/{libraryId}/change-sets/{changeSetId}/reviews
`

## 8. Polling 간격 (UD-04 확정)

| 단계 | Polling 간격 | 근거 |
| --- | --- | --- |
| SCANNING | 2초 | 진행도 표시 필요 |
| PROCESSING | 2초 | 진행도 표시 필요 |
| PLAN_REVIEW·QUESTION_WAITING | 1초 | 사용자 입력 대기 |
| 기본 | 2초 (또는 Retry-After 헤더) | UD-04 확정 |
