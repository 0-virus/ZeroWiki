# 일간 작업 일지

## 오늘 한 일 확인

- 한국 시간(`Asia/Seoul`)을 기준으로 일지를 작성할 날짜를 정한다. 사용자가 날짜를 지정하면 그 날짜를 쓴다. 현재 대화에서 그날 실제로 결정하거나 작성·수정·검증한 일을 추린다. 제안, 설계, 구현, 검증을 구별해 실제 진행 단계에 맞는 동사를 쓴다.
- 이 저장소에서 커미터 시각이 해당 날짜에 속하는 커밋을 확인한다. 아래 명령의 `YYYY-MM-DD` 두 곳에 같은 날짜를 넣는다. 제목만으로 결과가 불분명하면 `git show <해시>`로 변경 내용을 읽는다.

```sh
git log HEAD --branches --since-as-filter='YYYY-MM-DD 00:00:00 +0900' --until='YYYY-MM-DD 23:59:59 +0900' --format='%h %cI %s' --name-status
```

- 커밋이 없어도 대화에서 확인한 작업을 기록할 수 있다. 같은 결과가 대화와 여러 커밋에 반복되면 한 번만 쓴다. 대화와 커밋 모두에서 기록할 작업을 찾지 못하면 빈 일지를 만들지 않는다.

## Notion 위치와 날짜 확인

- Notion 연결 목록에서 **개인 프로젝트** 계정을 사용한다. [작업 일지](https://app.notion.com/p/420f8dff882580d88390e3da32428142)의 상위 경로가 `끝내주는 위키 만들기 → 할 일 목록`인지 확인한 뒤 안쪽의 `Daily Log`를 연다. 링크가 바뀌면 같은 계정에서 프로젝트 이름을 검색해 이 경로를 따라간다.
- `Daily Log`의 데이터 소스와 현재 기본 템플릿을 읽는다. 현재 템플릿 이름은 `Daily Log 양식`이며 날짜별 일지는 제목 속성 `이름`에 `YYYY-MM-DD`를 쓴다. 최종 편집 일시는 과거 일지를 고쳐도 바뀌므로 날짜 식별에 쓰지 않는다.
- 이 데이터 소스에서 날짜 제목이 정확히 일치하는 페이지를 조회한다. 보기를 사용할 때는 필터가 날짜를 가리지 않는지 확인하고 마지막 페이지까지 조회한다. 일치하는 페이지가 여럿이면 링크를 보여 주고 갱신 대상을 확인한다.

## 작성 및 갱신

- 기본 양식의 `금일 작업 내용`을 1단계 제목으로 쓰고 큰 작업마다 결과를 알아볼 수 있는 2단계 제목을 붙인다. 그 아래에 **작업별 2~3개의 짧은 글머리표**로 무엇을 했고 어떤 동작·결정·확인 결과가 남았는지 적는다. `다음 할 일`과 `노트`는 작성하지 않고 제목만 남긴다.
- 날짜 페이지가 없으면 해당 데이터 소스에 한 장을 만든다. 템플릿 원본은 서식 참고용이다. 생성 직후 본문 첫 제목이 누락되었는지 확인한다. 빠졌으면 같은 페이지 맨 앞에 `<h1>금일 작업 내용</h1>`을 삽입한다.
- 날짜 페이지가 있으면 본문을 먼저 읽는다. 같은 작업의 새 사실은 그 소제목 안에 합치고, 다른 결과만 새 소제목으로 추가한다. 사용자가 직접 쓴 내용과 이전 세션에서 기록한 작업을 보존하며, 달라진 대목만 수정한다. 내용이 이미 반영되어 있으면 쓰기 없이 기존 링크를 반환한다.
- 쓰기 응답이 불분명하면 날짜와 본문을 다시 조회한 뒤 누락된 변경만 적용한다. 사용자에게 날짜 페이지 링크와 생성·갱신·변경 없음 중 해당 결과를 알려 준다.
